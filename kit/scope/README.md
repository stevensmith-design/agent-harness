# Scoping

Three files, one output.

- `context.md` — gathering context from wherever it lives, before any question is asked.
- `interview.md` — the questions, in order. Skip whatever the context already answered.
- `architecture-doc.template.md` — what the answers become.

The architecture document is agreed before anything is built. It is also the standalone deliverable of a scoping-only engagement: it has value even if no harness is built, because it says whether one is worth it and why.

**The three questions that most often change the answer:**

1. **Fitness** (§0) — is a harness required? A recommendation, never a gate: the person decides.
2. **What failure looks like when the output is fine** (§1.3) — the prime directive, and the one that needs a real conversation.
3. **Is the standard scorable yet** (§4) — which sets the rung, and which is about the corpus, not the team.

And one that is cheap to ask and expensive to skip: **§5b, what do the people who receive this work currently have to ask about?** Whatever they ask is what the documents do not hold — and it is almost never shapes, which get generated. It is the rules.
