# Judged examples — what "good" looks like here

Taste that no rule states yet, written down so an agent can compare instead of
guess. One file per example:

```markdown
# <screen> — good | bad
![](<screenshot>.png)
**Why:** <one sentence a reviewer could apply to a different screen>
**Judged by:** <name> · <YYYY-MM-DD>
```

The reason is the part that teaches. "Looks clean" teaches nothing. "The primary
action is the only filled button on the screen" can be applied to the next screen.

When two examples share a reason, that reason is ready to be a written rule in
`DESIGN.md` or the design rulebook. When a rule can be measured, it moves to
`make render-audit`. Delete an example once a rule or a check covers it.
