# Contributing

Thanks for looking. Small, focused changes are easiest to review.

## Before you start

- For anything larger than a small fix, open an issue first, so nobody builds something that won't be merged.
- Work on a branch, not the default branch.

## Checks

This repository uses a harness that runs its checks through `make`:

```
make check            # lint, format, typecheck, tests and the fast gates
```

Paste the real output in your pull request. If something couldn't be checked, say so under **Not verified** in the template; that is a fine answer, an empty section is not.

## Reporting a security problem

Please don't open a public issue. See [`SECURITY.md`](SECURITY.md).
